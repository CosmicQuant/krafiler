## 1. Executive Summary

This plan transitions KRAFILER from a single-user, on-premise monolith (SQLite + Redis/BullMQ + local filesystem) to a **multi-tenant SaaS** on Firebase + Google Cloud Platform. The migration preserves all existing functionality — KRA portal automation, payroll engine, practice management — while adding authentication, subscription billing, and cloud-native scalability.

### Key Principles
- **Bridge-first, then rebuild:** Run SQLite in Cloud Run initially, then migrate to Firestore in phases.
- **Security-first:** Fix plaintext credentials, missing auth, and hardcoded secrets before any public deployment.
- **Worker isolation:** The Playwright worker remains a single-instance Cloud Run service (concurrency: 1, max-instances: 1) to respect KRA rate limits.
- **Real-time UX:** Replace 2-second polling with Firestore `onSnapshot` listeners for job progress.
- **Kenya-first billing:** Paystack integration for M-Pesa, cards, and bank transfers.

### Critical Pre-Flight Fixes (Non-Negotiable)
1. **Re-enable AES-256-GCM encryption** for KRA passwords before they leave the API handler.
2. **Add Firebase Auth middleware** to all protected routes (`/api/clients/*`, `/api/payroll/*`, `/api/tax/*`).
3. **Remove hardcoded JWT fallback** — fail loudly if `JWT_SECRET` is missing.
4. **Protect receipts** with auth or signed URLs; remove `express.static` for `/api/receipts`.

### Identified Issues (from code review)

| Issue | Severity | Impact |
|---|---|---|
| KRA passwords sent in plaintext to BullMQ | **Critical** | Credentials exposed in Redis, logs, job inspect |
| No auth middleware on most API routes | **Critical** | Anyone can access client data, file returns, download payslips |
| Hardcoded JWT_SECRET fallback | **High** | Employee portal tokens trivially forgeable |
| `express.static` serves receipts without auth | **High** | Receipts accessible by URL guessing |
| Worker file is 1,400+ lines, mixed concerns | **Medium** | Unmaintainable, hard to test, dead code |
| SQLite with no FK constraints | **Medium** | Orphaned records, data integrity risk |
| `frontend/package.json` lists 100+ direct deps (mostly transitive) | **Medium** | Supply chain bloat, upgrade fragility |
| `api.ts` is a bare fetch wrapper | **Low** | No auth header injection, no error handling, no JSON parsing |
| No tests, no lint, no formatter | **Low** | Regressions caught only at runtime |
| `.archive/` directory with 35+ patch scripts | **Low** | Repo clutter, confusing history |

### Service Decisions

| Capability | Current | Target | Rationale |
|---|---|---|---|
| **Auth** | None / JWT (employee portal only) | Firebase Auth (Google Sign-In) | Zero-config OAuth, built-in token refresh, frontend SDK |
| **Database** | SQLite (local file) | Firestore (Native) | Real-time sync, multi-tenant security rules, serverless scale |
| **Queue** | BullMQ + Redis | Cloud Tasks | No Redis infra to manage; per-user queue isolation; native GCP IAM |
| **Files** | Local disk | Cloud Storage | Persistent, signed URLs, lifecycle rules, shared between API & worker |
| **Frontend Hosting** | `vite dev` (localhost) | Firebase Hosting | CDN, SSL, SPA rewrites, zero-config |
| **API Hosting** | Local `npm run dev` | Cloud Run | Containerized, auto-scaling, HTTPS |
| **Worker Hosting** | Local `npm run worker` | Cloud Run (single instance) | Same container, different command; `--concurrency 1 --max-instances 1` |
| **Secrets** | `.env` file | Secret Manager | No secrets in images, rotation support, audit logging |
| **Payments** | None | Paystack (M-Pesa/cards) | Kenya-first; lower fees than Stripe |

## 4. Service Mapping

### 4.1 Firebase Authentication
- **Provider:** Google Sign-In (only provider for v1).
- **Token flow:**
  1. Frontend signs in via `signInWithPopup(auth, googleProvider)`.
  2. Frontend gets Firebase ID Token via `user.getIdToken()`.
  3. ID Token sent in `Authorization: Bearer <token>` header on every API call.
  4. API verifies token with `firebase-admin/auth` `verifyIdToken()`.
  5. API extracts `uid`, `email`, and fetches user document from Firestore for plan/subscription checks.

### 4.4 Cloud Tasks Queue Design

**One queue per user** (created on first successful payment):

```typescript
// Cloud Function: onUserPaymentConfirmed
import { v2 } from '@google-cloud/tasks';

const client = new v2.CloudTasksClient();

async function createUserQueue(userId: string) {
  const queuePath = client.queuePath(projectId, region, `krafiler-user-${userId}`);
  await client.createQueue({
    parent: client.locationPath(projectId, region),
    queue: {
      name: queuePath,
      rateLimits: {
        maxDispatchesPerSecond: 0.016,   // 1 per minute
        maxConcurrentDispatches: 1,       // Never overlap

      retryConfig: {
        maxAttempts: 1,                   // Fail fast (same as current BullMQ)
        minBackoff: { seconds: 60 },
      },
    },
  });
}
```

```typescript
app.post('/process-job', async (req, res) => {
  const { jobId } = req.body;
  const jobRef = db.collection('jobs').doc(jobId);
  const jobDoc = await jobRef.get();
  if (!jobDoc.exists) return res.status(404).send('Job not found');

  const jobData = jobDoc.data() as JobDoc;

  // Verify caller is Cloud Tasks (OIDC token already verified by Cloud Run IAM)

  await jobRef.update({ status: 'processing', startedAt: FieldValue.serverTimestamp() });

  try {
    const result = await processFilingJob(jobData);
    // Upload receipt to Cloud Storage
    const receiptUrl = await uploadReceipt(result.receiptPath, jobId);

    await jobRef.update({
      status: 'completed',
      progress: 100,
      'artifacts.receiptUrl': receiptUrl,
      completedAt: FieldValue.serverTimestamp(),
    });

    // Update client status
    await db.collection('clients').doc(jobData.clientId).update({
      [`status.${jobData.taxObligationType}`]: 'filed',
      [`lastFiled.${jobData.taxObligationType}`]: {
        date: FieldValue.serverTimestamp(),
        receiptUrl,
      },
    });

    res.status(200).json({ success: true });
  } catch (error) {
    await jobRef.update({
      status: 'failed',
      error: {
        message: (error as Error).message,
        code: 'FILING_ERROR',
        retryable: false,
        failedAt: FieldValue.serverTimestamp(),
      },
    });
    res.status(500).json({ error: (error as Error).message });
  }
});
```

### 4.6 Auth Middleware (Express)

```typescript
import { getAuth } from 'firebase-admin/auth';
import { getFirestore } from 'firebase-admin/firestore';

const db = getFirestore();

export async function verifyAuth(req: Request, res: Response, next: NextFunction) {
  const authHeader = req.headers.authorization;
  if (!authHeader?.startsWith('Bearer ')) {
    return res.status(401).json({ error: 'Unauthorized' });
  }

  const idToken = authHeader.split('Bearer ')[1];

  try {
    const decoded = await getAuth().verifyIdToken(idToken);
    const userDoc = await db.collection('users').doc(decoded.uid).get();
    const userData = userDoc.data();

    if (!userData || userData.subscriptionStatus === 'cancelled') {
      return res.status(403).json({ error: 'Subscription required' });
    }

    req.user = {
      uid: decoded.uid,
      email: decoded.email || '',
      plan: userData.plan,
      subscriptionStatus: userData.subscriptionStatus,
    };

    next();
  } catch {
    res.status(401).json({ error: 'Invalid token' });
  }
}

// Apply to all protected routes
app.use('/api/clients', verifyAuth);
app.use('/api/payroll', verifyAuth);
app.use('/api/tax', verifyAuth);
app.use('/api/portal', verifyAuth);
```

### 4.7 Subscription Enforcement Middleware

```typescript
const PLAN_LIMITS = {
  starter:  { maxClients: 5,  maxFilings: 25 },
  solo:     { maxClients: 15, maxFilings: 100 },
  practice: { maxClients: 75, maxFilings: 500 },
  firm:     { maxClients: Infinity, maxFilings: Infinity },
};

export async function checkLimits(req: Request, res: Response, next: NextFunction) {
  const { uid, plan } = req.user;
  const limits = PLAN_LIMITS[plan as keyof typeof PLAN_LIMITS];
  const userDoc = await db.collection('users').doc(uid).get();
  const userData = userDoc.data();

  if (req.path === '/clients' && req.method === 'POST') {
    if (userData.clientCount >= limits.maxClients) {
      return res.status(403).json({ error: 'Client limit reached. Upgrade your plan.' });
    }
  }

  if (req.path.includes('/tax/file') && req.method === 'POST') {
    if (userData.filingsThisMonth >= limits.maxFilings) {
      return res.status(403).json({ error: 'Monthly filing limit reached. Upgrade your plan.' });
    }
  }

  next();
}
```

#### CRITICAL — Frontend duplicates core IP

These files expose Kenyan tax calendar logic and the entire payroll proration engine. **Must be moved to backend API immediately.**

### 5.3 Firestore Security Rules

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isAuthenticated() {
      return request.auth != null;
    }

    function isOwner(userId) {
      return isAuthenticated() && request.auth.uid == userId;
    }

    function getUserData() {
      return get(/databases/$(database)/documents/users/$(request.auth.uid)).data;
    }

    function isActiveSubscription() {
      let user = getUserData();
      return user.subscriptionStatus == 'active' ||
             (user.subscriptionStatus == 'past_due' && user.subscriptionEndsAt > request.time);
    }

    function withinClientLimit() {
      let user = getUserData();
      let limit = {
        'starter': 5,
        'solo': 15,
        'practice': 75,
        'firm': 999999
      }[user.plan];
      return user.clientCount < limit;
    }

    match /users/{userId} {
      allow read: if isOwner(userId);
      allow create: if isOwner(userId);
      allow update: if isOwner(userId);
      allow delete: if false;
    }

    match /clients/{clientId} {
      allow read: if isAuthenticated() && resource.data.ownerUid == request.auth.uid;
      allow create: if isAuthenticated()
        && request.resource.data.ownerUid == request.auth.uid
        && isActiveSubscription()
        && withinClientLimit();
      allow update: if isAuthenticated() && resource.data.ownerUid == request.auth.uid;
      allow delete: if isAuthenticated() && resource.data.ownerUid == request.auth.uid;
    }

    match /employees/{employeeId} {
      allow read: if isAuthenticated() && resource.data.ownerUid == request.auth.uid;
      allow create, update, delete: if isAuthenticated() && resource.data.ownerUid == request.auth.uid;
    }

    match /payrollRuns/{runId} {
      allow read: if isAuthenticated() && resource.data.ownerUid == request.auth.uid;
      allow create, update, delete: if isAuthenticated() && resource.data.ownerUid == request.auth.uid;
    }

    match /payrollRuns/{runId}/entries/{entryId} {
      allow read: if isAuthenticated() && get(/databases/$(database)/documents/payrollRuns/$(runId)).data.ownerUid == request.auth.uid;
      allow write: if isAuthenticated() && get(/databases/$(database)/documents/payrollRuns/$(runId)).data.ownerUid == request.auth.uid;
    }

    match /jobs/{jobId} {
      allow read: if isAuthenticated() && resource.data.ownerUid == request.auth.uid;
      allow create: if isAuthenticated() && request.resource.data.ownerUid == request.auth.uid;
      allow update: if isAuthenticated() && resource.data.ownerUid == request.auth.uid;
      allow delete: if false;
    }

    match /jobs/{jobId}/logs/{logId} {
      allow read: if isAuthenticated() &&
        get(/databases/$(database)/documents/jobs/$(jobId)).data.ownerUid == request.auth.uid;
      allow write: if false;  // Only worker writes logs
    }

    match /subscriptions/{subId} {
      allow read: if isAuthenticated() && resource.data.userId == request.auth.uid;
      allow write: if false;  // Only Cloud Functions write
    }
  }
}
```

| **KRA blocks Cloud Run IP** | High | Low | Concurrency=1, rotate profiles, respect rate limits | Manual IP rotation not possible; rely on KRA whitelist request |
| **Cloud Run cold start too slow** | Medium | High | Show "warming up" UI; optional Cloud Scheduler keep-alive | Increase `--min-instances` to 1 |
| **Paystack webhook failures** | Medium | Low | Retry logic, dead letter queue, manual reconcile | Re-process from webhook logs |
| **Data migration corruption** | High | Low | Test migration on copy; validate row counts; keep SQLite backup | Revert to SQLite backend |
| **Firestore query costs explode** | Medium | Low | Monitor read counts; use composite indexes; cache in frontend | Optimize queries; add caches |
| **Subscription enforcement bypass** | High | Low | Enforce in BOTH Firestore rules AND API middleware | Patch API; update security rules |
| **Worker concurrency > 1 by mistake** | High | Low | Infrastructure-as-code (Terraform) with locked values | Immediate `gcloud run deploy` with `--concurrency 1` |

### Rollback Procedures

**Database rollback:**
1. Change `DATABASE_MODE=firestore` back to `DATABASE_MODE=sqlite` in env vars.
2. Restart API Cloud Run service.
3. Frontend falls back to SQLite API endpoints (keep them behind feature flag for 2 weeks).

**Queue rollback:**
1. Change `QUEUE_MODE=cloudtasks` back to `QUEUE_MODE=bullmq`.
2. Re-enable Redis/Memorystore.
3. Restart API and Worker.

**Deployment rollback:**
```bash
# Roll back to previous image
gcloud run deploy krafiler-api --image gcr.io/PROJECT_ID/krafiler-backend:PREVIOUS_TAG
gcloud run deploy krafiler-worker --image gcr.io/PROJECT_ID/krafiler-backend:PREVIOUS_TAG
```
